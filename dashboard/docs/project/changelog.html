[5.0.0] - 2026-11-20

This release follows 4.0.1 on npm. 4.0.0 and 4.0.1 were published from a tree that was never pushed to this repository, so this changelog goes straight from 3.5.0 to 5.0.0 and every entry below is relative to 3.5.0. It is a major version because Node.js 22.19 is now the minimum and some operations were removed rather than faked (both under Changed). The xactions-mcp wrapper moves to 5.0.0 with it and depends on xactions ^5.0.0.

Fixed

  • Every documented import path works from an installed package. About thirty examples in the docs, tutorials, skills and README failed when copied, with ERR_PACKAGE_PATH_NOT_EXPORTED or a missing export. xactions/spaces/agent is now xactions/spaces, ten examples import manager functions from the module that defines them instead of the root, and the teams example is rewritten against teamManager.js. tests/docs/import-paths.test.js resolves every from 'xactions…' in the docs through the package's exports map and fails on a new broken example. (#175)
  • The sentiment analyzer no longer scores every emoji as both positive and negative. Its character classes lacked the u flag, so they matched UTF-16 surrogate halves, which nearly all emoji share. (#177)
  • Workflow triggers survive a restart. They were registered in memory only when a workflow was created or updated, so after the API server restarted every webhook answered 401 and every interval and schedule stopped until each workflow was saved again. The server now registers the trigger of every stored, enabled workflow at start, before it answers any workflow request.
  • Logged-out reads work again for media, thread and download. X now answers its media-tab and TweetDetail queries with 403 to visitors without a session, so the three commands AGENTS.md lists as public failed for anyone not logged in. Logged out, media and profile downloads read the media off the public timeline, and thread and single-post downloads read through the guest rails the hosted MCP server uses. With a session nothing changes. tests/cli/loggedOutReads.test.js.
  • x_login reports whether the login worked, and the caps follow it. It returned success for any cookie, a dead one included, and the daily action caps kept charging the account resolved before the switch. It now checks that x.com shows a signed-in session, returns the handle, and charges that account from then on.
  • A flaky test is not flaky any more. addJitter draws from a Gaussian with a 30% floor; the test asserted one draw was above 50% of the base, which fails about one run in 160. It now checks the floor on every draw and closeness on the average of 2,000.
  • x_schedule_post reaches the composer. The MCP dispatcher sent every x_schedule_* name to the scheduler queue's handler, which knows only x_schedule_add, _list and _remove, so x_schedule_post failed on every call with "Unknown competitive tool". tests/mcp/tool-contract.test.js now reads dispatchTool's branches and fails on any tool routed to a handler with no case for it.
  • MCP tools that answer { error } are reported as errors. Only { success: false } set isError, so x_analyze_sentiment without text, x_monitor_reputation with an unknown action, the AI tools without OPENROUTER_API_KEY and x_unfollow_all without confirm reached the agent as successes, and an approved draft that returned one was marked executed.
  • xactions info prints the installed version instead of a hard-coded v3.0.0, and xactions mcp-config --client <unknown> exits 1 naming the supported clients, instead of printing Claude Desktop's config and exiting 0.
  • The Docker image builds again. npm ci in the deps stage failed on better-sqlite3: it has no install script, so npm runs node-gyp rebuild, which needs Python and make even when the package's prebuilt binary means nothing is compiled, and node:22-slim has neither. The deps stage installs them; the runtime image is unchanged.
  • node scripts/build-mcpb.mjs packs again. The bundle's node_modules/deepmerge is a link to the patched vendor/deepmerge, which was not staged, so the pack step failed on a dangling link.
  • A backlog of one slow job type no longer stops every other job. The API's operations queue ran one Bull processor eight jobs at a time and enforced each type's own limit only after Bull had claimed the job, by waiting inside the processor. Jobs waiting on their type held the claimed slots and showed as started, so nine queued smartUnfollow jobs (one at a time) left one running and seven waiting in slots, and no other type started until the backlog drained, which could take hours. The queue is now one Bull queue per concurrency class (api/services/jobQueue.js): every type that can share a slot stays on the shared operations queue at XACTIONS_WORKER_CONCURRENCY (default 8), and each type that runs one at a time (concurrency: 1, 25 types including smartUnfollow, bulkExecute, autoFollow and spaceJoin), or that declares the new ownQueue: true because it runs for hours (personaRun, discoveryTrendingMonitor), has a queue of its own at its own limit, where a waiting job holds nothing. Job ids, status, cancel, history, repeating jobs, socket events, callbacks and the Operation row work across every queue as before, and a job left on the shared queue by an earlier version still runs. The queues share one command and one pub/sub Redis connection, so 28 queues hold 30 connections per process rather than 84. Shutdown now closes every queue, and the 30 second drain limit applies (a pause awaited first waited for running jobs with no limit). Covered against a real Redis in tests/api/jobQueue.redis.test.js, which fails on the previous version, and without Redis in tests/api/jobQueue.test.js.
  • GET /api/workflows lists your workflows again. The store's summaries left out userId, so the route's owner filter matched nothing and every user but an admin got an empty list. Both stores (src/workflows/store.js) now carry it.
  • Fixes to the dashboard reach returning visitors within minutes. api/server.js served everything under public/ as immutable for a year, and the dashboard's images the same, though no file name is content-hashed; deploy/gcp/nginx.conf did it for every .js and .css too, so a browser kept last year's sidebar.js against this year's HTML and API. Scripts, styles, HTML and data files are now cached for five minutes and revalidated against the ETag, images, fonts and video for a day, matching dashboard/_headers. Covered in tests/api/security.test.js.
  • The mempool guide no longer teaches Blocknative's retired API. Blocknative shut its API down on June 19, 2026, and docs/seo-articles/mempool-api-guide.md still opened with its SDK. The Ethereum section now uses standard JSON-RPC that any node or provider answers: eth_subscribe for pending transactions (watching an address, a contract's calls and large transfers) and eth_feeHistory for gas estimates, with no vendor SDK or key. The generator, scripts/gen3.js, carries the same text, so regenerating the article does not bring Blocknative back. Reported by @cmdenney in #30.
  • The MCP browser tools stop timing out before they act. About forty navigations in src/mcp/local-tools.js and src/mcp/server.js (x_post_tweet, x_like, x_reply, x_retweet, x_delete_tweet, x_mute_user, x_send_dm, x_get_replies, x_get_likers, x_quote_tweet and the rest) still waited for networkidle2, which never settles on x.com, so each one burned Puppeteer's 30 second timeout and threw. The same was true of the scrapers behind x_get_likes, x_get_media, x_get_list_members, x_get_notifications, x_get_trends and x_get_spaces, the workflow actions, and the persona agent's browsing. They now share one helper, gotoAndRender() in src/utils/navigation.js, which loads to domcontentloaded and waits up to 15 seconds for the element the caller is about to use, without failing if it never shows. The finding and the first version of the helper are @devlewicki's, from #100, which fixed the profile scrapers the same way. Covered in tests/utils/navigation.test.js.
  • x_post_tweet posts on the current X UI, and the other compose tools say whether X accepted the post. /compose/tweet now redirects to /compose/post, and the text area is a contenteditable editor that ElementHandle.type() does not reach, so the button stayed disabled and the tool answered "Could not post tweet". The composer is now opened from /home through the sidebar button, the editor is clicked and typed into through the keyboard, and the text is read back before anything is posted (src/mcp/composer.js). x_post_thread, x_create_poll, x_schedule_post, x_reply, x_quote_tweet and the workflow postTweet and reply actions use the same flow, and none of them reports success any more until X confirms it: the typed text has left the composer, or X shows a toast that is not an error ("Whoops! You already said that." is a failure). x_schedule_post sets the date and time in X's schedule dialog instead of confirming its default and reporting the requested time, and x_create_poll sets durationMinutes instead of ignoring it; both stop without posting if a field cannot be set. x_auto_comment passed tweetUrl to x_reply, which takes url, and counted every attempt as a comment. Covered in tests/mcp/composer.test.js. By @MurlocYat in #25.
  • x_clear_bookmarks clears bookmarks again. It opened the bookmarks page's overflow menu and looked for "Clear all bookmarks", an item X has removed, so it failed on every call. It now removes bookmarks one at a time with 1 to 3 second pauses and a bounded cooldown on X's rate-limit notice, counts a removal only after that post has left the feed, stops instead of clicking a post again when X does not confirm a removal, and reports nothing removed as success only when X shows its empty state (src/mcp/clearBookmarks.js). The console script browser/clearAllBookmarks.js also runs on x.com/i/history, where some accounts are redirected from the bookmarks page, and checks only the path, so a search for "/bookmarks" no longer passes its guard. Covered in tests/mcp/clear-bookmarks.test.js and tests/scripts/clearAllBookmarks.test.js. By @CameronHN in #88.
  • xactions download works. It was handed the wrong scraper and failed on every target with "scrapers.scrapeMedia is not a function".
  • xactions ask and the x_ask tool work from an npm install. Their documentation index was not in the published package, so every installed copy failed and reinstalling could not fix it. The CI tarball smoke test now runs ask and loads the MCP server.
  • Commands exit non-zero when they fail. 86 error paths in the CLI printed the error and exited 0; bulk and engage exited 0 with failed actions; schedule run reported a failed job as executed. reputation with no working model reported "100/100 A+, reads clean"; it now fails. analyze -o with --json or --compact printed twice and never wrote the file. non-followers --json printed a human report before the JSON. search --filter people returned tweets. audience printed undefined. The ai commands rejected logged-in users. migrate --limit was ignored. ask --no-sources was ignored. scrape ignored --compact and --fields. --limit abc and monitor --interval abc are now refused instead of becoming NaN (a 1 ms poll), and -o creates its folder before a long scrape starts rather than failing after it.
  • xactions brief no longer caches an empty timeline as complete. An empty page from X was stored for six hours and reported as an account with nothing to say; it is now a per-account failure.
  • XACTIONS_HOME moves everything. Login, connect, doctor, saved sessions, the CRM, history, workflows, engage state, personas, bulk progress, the scheduler, graphs, RSS and evergreen state all ignored it and wrote to ~/.xactions. The CLI reference documented five environment variables nothing read; they are gone.
  • import('xactions/cli') no longer runs the CLI and exits the host process; it exports program.
  • Search, media and long posts. searchTweets and searchUsers stopped after two pages (X moves the cursor into a replace instruction); scrapeMedia stopped after one; posts over 280 characters were cut off; Mastodon followers repeated page one. A resumed checkpoint now returns what the interrupted run collected instead of only the rest. 5xx responses are retried for reads, the Scraper proxy option is honoured, a logged-in client no longer needs a guest token, and cookie imports drop expired and duplicate .twitter.com cookies.
  • MCP handlers that reported success while doing nothing: x_unfollow_all never unfollowed anyone, x_follow_engagers followed no one, x_smart_unfollow had nothing to act on, x_quote_tweet returned success without checking, x_crm_tag reported an unknown contact as tagged, and a tool that answered { success: false } was counted as done. Each now acts or fails. x_smart_unfollow advertises only the criteria it can check. x_bulk_execute's block action called a function that does not exist and reported every block as done; the bulk executor now fails on a missing action. One x_rss_add call without a URL crashed the whole server.
  • The MCP HTTP transport serves hosted clients. It refused any Host header but loopback names; XACTIONS_MCP_ALLOWED_HOSTS names the hostnames to accept, and a token-protected server accepts any. The x402 gate skipped /mcp/ and /MCP, and answered 500 in production with payments switched off.
  • API services: scheduled and manual unfollower scans ran logged out (the stored cookie was never decrypted); a failed scrape was taken as "every follower lost"; follower diffs blocked the event loop for 24 s at 5,000 followers; every A2A task submission answered 500; unfollow-non-followers unfollowed real mutuals; the queue hung forever without Redis and ignored REDIS_URL; duplicate Stripe webhooks answered 500 for days; retried jobs sent job.failed callbacks for attempts that later succeeded; cancelled jobs kept running; operation-queue writes were not charged against the daily caps, and now stop at the cap with a partial result.
  • Media downloads no longer delete a just-downloaded file when the dedupe link fails, and a slow large download is no longer killed at 60 s. The live pipeline no longer reconnects once a second forever when x.com drops it just after the config frame. Pooled browsers no longer share one cookie jar across accounts. Notifications honour the channel they are sent to, time out, and no longer drop Telegram messages containing _.
  • Deployment: a failed migration no longer starts the server on a half-migrated schema; the Render worker could not decrypt sessions the API saved; compose workers were permanently unhealthy; dashboard JS was cached as immutable for a year under unchanging names.
  • npm run docs:check catches what it missed. The count audit ignored llms.txt and llms-full.txt, "a 56-command CLI", and tool counts whose "MCP" sat on another line of the paragraph, so AGENTS.md and CLAUDE.md said 152 tools while the server served 155. The registry check now runs before regeneration in CI, so a stale server.json or smithery.yaml fails the build.
  • Ask answers no longer abort themselves. The /api/ask route aborted on the request's close event, which Node 24 fires as soon as the body is read, so every streamed answer ran with its signal already set and the first failed LLM lane ended the answer instead of falling through to the next. It now aborts only when the response closes before it ends. Reported by the XActions Chat work, which fixed the same pattern in its own route.
  • Accounts registered with a dotted or tagged Gmail address can sign in by email. Registration stores the address through normalizeEmail(), which for Gmail drops dots and +tags (Foo.Bar+x@gmail.com is stored as foobar@gmail.com), but login matched only the lowercased input, so those accounts could sign in by username and never by email. Login now matches both the lowercased address and the normalized form registration stores (api/routes/auth.js, tested in tests/api/login-email.test.js).
  • xactions followers and xactions search no longer fail with HTTP 404:. X serves Followers and SearchTimeline only over POST and answers a GET with an empty 404. #42 moved the http scraper to POST, but the CLI reads through Scraper in src/client, which kept its own GET requests, so both commands still failed for every user. Every GraphQL read in src/client/api now goes through graphqlQuery(), which picks the transport from the same graphqlRequestMethod() map the http scraper uses, so the next operation X moves is fixed in both clients by adding it there once. Scraper.getFollowers() and Scraper.searchTweets() / searchProfiles() are fixed for library users too. Covered in tests/client/graphqlQueries.test.js. Reported by @n4s3r in #99.
  • scripts/scrapeFollowers.js no longer stops after a couple of dozen followers. It gave up after five passes with no new rows, about 7.5 seconds, so a list X had throttled or was still loading read as finished. It now clicks X's Retry button when the list pauses, does not count a pass as a stall while the loading spinner is showing, scrolls one screen at a time instead of a fixed 800px, and says so when X stopped serving rows before the limit. The 200-scroll cap, which made the advertised 5,000-follower limit unreachable, is now MAX_SCROLLS: 1000. Reported by @n4s3r in #99.
  • xactions doctor --refresh-ids no longer blames your network when x.com changed clients. Logged-out x.com now serves a newer web client from abs.twimg.com/x-web/, built on Relay persisted queries, with none of the classic bundles query-ID discovery reads. Discovery reported "no main bundle in HTML" and doctor told you to check your network and proxy. It now recognises the new client, tags the failure X_WEB_CLIENT, and doctor says what is true: the query IDs shipped with XActions stay in use and nothing on your machine needs fixing. Scraping was never blocked by this; a failed refresh already fell back to the shipped IDs.
  • TwitterHttpClient.graphqlPaginate() no longer loops forever on a stuck cursor. The relationship, tweet and search loops already stopped when X returned the same bottom cursor twice, but the generic paginator only stopped when the cursor disappeared, so with its default limit of Infinity an unchanged cursor sent the same request to x.com indefinitely. It now treats an unchanged cursor as the end of the list. Covered in tests/http-scraper/client.test.js.
  • xactions schedule and the x_schedule_* MCP tools keep their jobs. Every adapter passed action: where the scheduler requires command:, and nothing loaded ~/.xactions/scheduler.json before using it, so each add overwrote the file and list, remove and run always saw an empty schedule. The CLI, the MCP tools and the /api/schedule routes now load the file first; an unknown job name answers 404 (or exits 1) instead of reporting success; a reloaded job keeps its last-run status and keeps firing while the daemon runs. The x_schedule_* descriptions promised a tweet queue that never existed and now describe the cron jobs they manage, and in stdio mode the MCP server sends console.log to stderr so module logging cannot corrupt the JSON-RPC stream. By @deptrai in #153.
  • Posting, quoting, deleting, liking and retweeting through src/client/api/tweets.js work. All seven write operations called endpoint.url(queryId) on GraphQL endpoint entries that had no url method, so every one crashed with endpoint.url is not a function. By @deptrai in #153.
  • MCP browser tools pick up a new login without a restart. The browser lane injected the saved session once at launch, so a login or connect from another process left it on a logged-out page and tools quietly returned []. It now fingerprints the session files and relaunches the browser when they change. By @deptrai in #153.
  • Twitter archive import reads bookmarks and Grok chats. The importer registered bookmarks.js and grok-chat-item.js but never folded them into the result, so both were parsed, dropped and always listed as missing. importTwitterArchive() now returns bookmarks and grok, exportArchive() writes them, and the HTML viewer shows real bookmarks instead of none (#156).
  • Browser scrapers no longer crash with puppeteer.use is not a function. In 4.0.1, src/utils/puppeteerStealth.js loaded puppeteer-extra through a dynamic import and called .use() on the module namespace, whose instance sits on default. The browser stack now loads through loadStealthPuppeteer() in src/utils/optionalDeps.js, which wraps puppeteer with puppeteer-extra's named addExtra export and registers the stealth plugin once per process, so it does not depend on how a default export crosses the CommonJS boundary. tests/utils/optionalDeps.test.js loads the real packages and checks that the plugin is registered. Reported and diagnosed by @G-Glitch404 in #87.
  • xactions/package.json can be imported again, as it could in 4.0.x; it is listed in exports.
  • Every xspace-agents package builds and passes its tests again (#143). The CLI could not compile because a licence header sat above its #! line, and xspace-agent join now rejects an unknown TTS_PROVIDER with a clear message instead of failing later. The widget's isSupported() type error and a missing ariaMatch fallback on the Space leave button are fixed, and the test suites, broken by Vitest 4 constructor mocks and by routes that moved their imports, pass in full: core 1784, server 455, cli 72, widget 90. The last open Dependabot alert there, fast-xml-parser below 5.12.0, is closed.
  • scripts/twitter/scrape-profile-posts.js no longer loses posts on long timelines. It scrolled by jumping to the bottom of the page, and X virtualizes the timeline, so posts between two extraction passes were never rendered and never scraped. It now scrolls one screen at a time. A rate-limited timeline that shows a "Retry" button was read as the end of the feed; the button is now clicked and the pass is not counted as a stall. The stall check counted kept posts, so a run of filtered-out posts ended the scrape early; it now counts posts seen. Emoji were missing from every scraped text because X renders them as images; they are read from the image alt text. Other accounts' posts that X renders on a profile (the parent of a reply, conversation context on /with_replies) were attributed to the profile being scraped; each post now carries author, and filters.excludeOtherAuthors (default true) drops them, retweets excepted. Long posts cut off behind "Show more" are flagged truncated: true instead of passing as complete. The CSV export gains Author and Truncated columns.
  • npx xactions-mcp starts the server again. The wrapper package imported the MCP server and relied on it starting itself, but the server only starts when it is the process entry point, so the wrapper hung without answering a client. packages/xactions-mcp/bin.js now calls main() explicitly. The wrapper also moves to xactions 4.0.1, which takes its npm audit from 32 findings (25 high) to 0. tests/mcp/xactions-mcp-wrapper.test.js runs the wrapper against this checkout and checks it answers initialize and lists tools over stdio.

Added

  • xactions/ai, xactions/engage and xactions/graph are exports, and a ./src/* export makes the documented xactions/src/... deep imports resolve. Deep imports are now part of the surface semver covers. (#175)
  • npm publish refuses a release nobody can trace. xactions 4.0.0 and 4.0.1 reached npm from a local commit (65a704b) that never reached GitHub, so latest pointed at code no one could read or rebuild (#87 reported a crash in src/utils/puppeteerStealth.js, a file the repository never had), while main still said 3.5.0. A prepublishOnly hook, scripts/check-release.mjs, now refuses a version that is already on npm or sorts at or below latest, and, outside CI, a dirty working tree or a HEAD that is not on GitHub's main. The tag-driven release workflow runs the same check before anything else and publishes with --provenance, so the npm page links the commit and workflow run that built each tarball. The next release must be above 4.0.1. Run npm run release:check to check a release before you tag it. Covered in tests/scripts/check-release.test.js.
  • XActions Chat: ask questions about any X account or post, with answers that cite the posts. Attach an account, a post or a thread at xactions.app/chat (now in the site sidebar), or paste an x.com link into the box, then ask: what they have been posting about, which numbers they shared, which posts did best, who they work with, or a draft post that tags them and quotes their own figures. Every [n] in an answer opens the post behind it. Attachments are read once with no login and kept with the conversation, so follow-ups make no X requests; conversations stay in the browser. Answers stream through the same free model lanes as Ask, with bring-your-own-key, and a context meter shows how much of the 24K budget the attachments use. Served at the edge by the Worker and by the Express API (POST /api/chat/context, POST /api/chat). Docs: docs/chat.md.
  • Read the whole of an X long-form Article without a browser (xactions article). TweetResultByRestId returns an Article's full body at article.article_results.result.plain_text, but only when the request's field toggles carry withArticlePlainText: true; x.com's web client sends false and gets the preview_text teaser alone. scrapeArticle(client, url) in src/scrapers/twitter/http/tweets.js makes that request and returns the title, the full plain-text body, preview and summary text, cover image, author and engagement counts, from an x.com/i/article/<id> URL, a status URL or a numeric id; it is also on the createHttpScraper() object, the xactions article command (--json, --compact), and the x_get_article MCP tool in the read group. A response with only the preview is reported as an error by the CLI and MCP tool, not printed as the article. To make this possible TwitterHttpClient.graphql() now takes an options.fieldToggles object, where before it had no way to send field toggles at all. It goes in the query string on GET and in the body on POST, and is left out when not given, so every existing read, including scrapeTweetById, sends the same request as before. Tested against fixtures in tests/http-scraper/articles.test.js, not against live x.com. By @mayconfrr in #45. Docs: docs/cli-reference.md.
  • CI now builds and tests xspace-agents. The pnpm/turbo monorepo under xspace-agents/ was never run by ci.yml, and its suites had drifted to 181 failures unnoticed. .github/workflows/xspace-agents.yml installs with the lockfile frozen, builds all five packages and runs the core, server, cli and widget suites. It only runs when xspace-agents/** or the workflow itself changes, so it costs nothing on other pushes.
  • Research the accounts you are about to tag (xactions brief). A post that tags an account and quotes its own numbers back gets far more interaction than a generic shout-out, but finding those numbers meant reading every timeline by hand. xactions brief --file accounts.txt --topic x402 reads each account and writes one brief: a ready-to-paste tag line; accounts that several of yours mention but you are not tagging yet; and per account, the figures it has posted about itself ($2.4M, 340%, 1.2M transactions) quoted in context with a link to each source post, its posts about the topic, its recent posts, its account statistics (from the same arithmetic as xactions analyze), and who it tags, reposts and links to. Markdown by default, for a doc or an LLM prompt; --json and --compact for scripts. Timelines are cached for six hours, so re-running a list while drafting only fetches what is new, and one bad handle is reported without costing the rest. Logged out, X often serves an account's popular posts instead of its latest; the brief detects that per account and says so rather than reporting stale posts as recent. Also the x_account_brief MCP tool in the analytics group. Docs: docs/brief.md.
  • One-command Google Cloud Run backend (npm run deploy:gcp). deploy/gcp/deploy.sh builds the repo Dockerfile (Node 24 with system Chromium) and deploys the API backend to Cloud Run, generating JWT_SECRET, SESSION_SECRET and ADMIN_API_KEY into Secret Manager. It boots and serves the read surface (scrapers, analytics, paid x402 reads) with no external credentials; DATABASE_URL, Twitter OAuth and Stripe are optional add-ons set in deploy/gcp/.env.gcp (gitignored), and it prints the exact wrangler command to point the Cloudflare Worker's API_ORIGIN at the new service. Docs: deploy/gcp/README.md.
  • CONTRIBUTORS.md credits the people behind XActions: code authors, and everyone whose bug report or investigation led to a fix, each with a link to their issue or PR. The README links it, and CONTRIBUTING.md says how credit is given from now on.
  • GET /api/messages/groups lists the group DMs your connected X account is in. Each group comes back with its id, name, avatar, member ids, admin ids, latest message, unread count and last activity, read live from X through the session you saved with POST /api/session/save-session.   • Webhook and media fetches connect to the address that was checked. The public-URL guard resolved a hostname, approved its addresses, and then let fetch resolve it again, so a DNS server answering the check with a public address and the request with 127.0.0.1 or a cloud metadata address got past it (DNS rebinding). publicFetch() in src/utils/publicUrl.js validates once and pins the connection to the validated address, with TLS still verified against the hostname.   • Third-party GitHub Actions are pinned to commit SHAs in the CI, deploy and Docker workflows, so a moved tag cannot change what runs with the repository's secrets. The release workflows are left to the release-pipeline work.
  • An A2A task belongs to the agent that created it. Any authenticated agent could read any task's messages and artifacts (GET /a2a/tasks/:id, /stream), cancel it, or append to its history, given its id. The creating caller's identity (credential type and key label or token subject) is now recorded on the task, and every other caller gets the same 404 as for a task that does not exist, so ids cannot be probed; agents with the admin permission still reach every task, and with authentication explicitly off nothing changes (src/a2a/taskManager.js, src/a2a/server.js). The run engine fell back to the server's own XACTIONS_SESSION_COOKIE whenever a run had no session, so a user without a saved X session who ran a workflow from the API acted as the operator's account, and the trigger listener handed every triggered run that cookie. Triggered runs (webhooks, intervals) on the API server now resolve the owner's saved session, as manual runs already tried to; a run whose owner has none fails with an error that says so. The CLI and MCP server keep using the machine's session. Webhook triggers were also never connected to the run engine on the API server, so a correctly signed webhook answered "Workflow triggered" and ran nothing; they are now (src/workflows/index.js, api/routes/workflows.js). Members now carry userId, with the username kept for display and updated on rename, and /api/teams/:id/members/:username resolves the name to the account that holds it now. [3.5.0] - 2026-08-04

Added

A CLI you can find your way around

  • Commands are grouped by task. Running xactions printed fifty-three commands in one flat alphabetical list, which tells a newcomer nothing about where to start and an experienced user nothing about what else exists. The root help now sorts them into eight task-shaped groups (Start here, Read an account, Followers and audience, Search and monitor, Write and grow, Automate, Move data, Low level) with an examples block and pointers to quickstart, per-command help, and completions. The grouping is reconciled against the live command tree, so a newly registered command still appears (under "More") and a group entry naming a deleted command is caught by a test rather than shipped.
  • xactions quickstart. A guided first run that reads what you already have configured and prints the three commands that will produce a result on your machine, then the directions worth exploring next. --json reports the detected setup state (config directory, whether a session is saved, guest or session tier) for scripts and CI.
  • xactions completion bash|zsh|fish. Tab completion for every command, sub-command, and flag, generated from the live Commander tree rather than a hand-maintained list, so it stays correct as commands are added. Descriptions are escaped per shell: an unescaped colon in zsh's name:description format silently truncated half the descriptions, and an apostrophe would have terminated the quoted string early.

Changed

  • --json now works on every read command. It was accepted by profile and analyze only; tweets, followers, following, non-followers, search, hashtag, thread, and media rejected it with error: unknown option '--json' despite the docs promising it worked everywhere. All eight now accept it.
  • --json outranks --output and --google-sheets. Passing both used to write the file and print nothing, so a script that piped --json while a config supplied --output silently produced no output. --json is now an explicit "give me the data on stdout" and wins.

Documentation

  • tutorial 05: Read any account like an analyst. Reading an account report properly (median versus mean, engagement per view versus per follower, lifetime versus recent cadence), comparing accounts, follower overlap, and tracking a series over time. Runs entirely on the guest tier.
  • tutorial 06: Everything is JSON. XActions as a pipeline component: the real field names, jq filters, chaining commands, exit codes in cron and CI, and where to switch from shell to the Node client. Every snippet was run against live data before it was written down.
  • CLI reference corrected. It carried a hardcoded Version 3.0.0, claimed an X account was required (most reads need none), and steered new users to xactions login (paste cookies out of DevTools) rather than xactions connect (log in through a real browser). It now documents the command groups, quickstart, and completion.

Security

  • packages/xactions-mcp raised off the vulnerable 3.4.4 dependency line, clearing the outstanding npm audit advisories. Released as 3.4.8 and carried into this version.

Fixed

Public reads work again, without a browser

  • Scraper.getProfile() returned HTTP 404 {"message":"Query not found"} for every call. The repo carried two independent tables of X GraphQL query IDs, and 11 of the client's had gone stale while the shared map stayed current. Query IDs now have exactly one home (src/scrapers/twitter/http/endpoints.js), and a test fails if a second copy reappears.
  • The HTTP client could not obtain a guest token at all. X answers a request with no browser User-Agent with a misleading HTTP 404 "Sorry, that page does not exist", which reads like a removed endpoint rather than a rejected client. Every request the client makes now carries one.
  • xactions profile printed Followers: 0 and exited 0. X stopped serving profile and timeline content to logged-out browsers, so the Puppeteer scrape found an empty page and the CLI reported the nothing it found as success. profile, tweets, followers, following, search, and non-followers now use the HTTP client, which is roughly an order of magnitude faster and needs no Chromium download.
  • xactions non-followers reported your entire following list as non-followers. It filtered on a followsBack flag the GraphQL follow lists do not carry, so the predicate matched everything. It now diffs the follower and following lists.
  • The MCP server answered AI agents with every field set to null (issue #27). x_get_profile and x_get_tweets had the same browser-path problem, which is worse in an agent context: an assistant cannot tell an empty result from a missing one, so it reports confidently wrong answers. Both now prefer the HTTP client and fall back to the browser.
  • Unauthenticated failures now say what to do. X restricts search, followers, likes, bookmarks, and DMs to logged-in sessions and answers a guest request with a bare 404. That surfaced as HTTP 404: Not Found, which sent people looking for a bug in XActions. It now raises AUTH_REQUIRED naming the endpoint and the fix. Errors also carry endpoint, httpStatus, and rateLimitReset, which positional constructor calls had been silently dropping.
  • xactions login now captures ct0 as well as auth_token. Without the CSRF token X treats the session as logged out, so session-tier endpoints kept failing after an apparently successful login.

Paid API

  • Every /api/ai/* endpoint returned 500 instead of 402. @x402/core v2 moved payment terms behind an accepts key; the flat v1 route shape made the SDK throw during route validation on every request. All 95 payment tests now pass against a live server.

Cross-platform

  • Every Bluesky scrape threw Cannot read properties of undefined (reading '_client'). The XRPC helper detached the SDK method from its namespace before calling it. Profiles, posts, and follower lists all work again.
  • Mastodon bios and posts contained raw HTML entities (&amp;, &#39;) after tag stripping.
